# LivelyCura Loop App

## Summary

Employee/workforce Expo application in the LivelyCura family. Its product name is **SERLP Team** (renamed from Loop / "SERLP Loop" on 2026-11-24); "Loop" survives only as the internal code name in the repo, IDs and identifiers. Source: [[../sources/livelycura-loop-renamed-serlp-team|Loop renamed SERLP Team]].

## Purpose

Current features support workspace selection, announcements, attendance, schedules and shifts, leave, payroll, personal information, profiles, and notifications.

## Stack

- Expo SDK 58, React Native 0.88, React 19.3, TypeScript 6 (upgraded from SDK 54 on 2026-11-24). Builds on Xcode 27 without workarounds; the old `patches/` (@expo/cli DeviceHub backport) and `plugins/` (pod deployment-target raise) are gone. Lowest iOS is 16.4, Android minSdk 24.
- React Navigation, Apollo Client/GraphQL, Redux Toolkit.
- Shared design system, GraphQL Codegen, EAS.
- Yarn.

## Architecture

`App.tsx` composes providers; `src/navigation` owns route structure. Workforce domains live directly under `src` with shared runtime in `apollo`, `redux`, `theme`, `system`, `hooks`, and `design-system`.

## Folder Ownership

- `workspace`, `profile`, `personal-info`, `login`: employee context.
- `attendance`, `schedule`, `shifts`, `leave`, `payroll`: workforce operations.
- `announcements`, `announcementDetails`, `notifications`: communication.

## Commands

- `yarn start`, `yarn ios`, `yarn android`, `yarn web`
- `yarn generate`
- `yarn type-check`, `yarn format:check`
- EAS profile-specific Android and iOS build commands in `package.json`

## Runtime/Deployment

Expo/EAS application with CI and preview/production deployment workflows.

## Durable Conventions

- Product credits (sign-in or version footers, document footers) say "by SERLP" / "Generated by SERLP", never LivelyCura; LivelyCura names only its real delivery service. Source: [[../sources/livelycura-credit-serlp-not-livelycura|Credit SERLP, not LivelyCura]].
- Personal information shows the person's own record as plain rows with no "Private" markers; new screens copy existing design-system patterns. Source: [[../sources/livelycura-match-existing-ui|Match existing UI]].
- The HRM review runs one feature at a time: report and decide only the current feature's items, leave finished features closed, park later-feature items silently until that feature is reached, and don't flag a message as vague when it already tells the user what happened. Source: [[../sources/livelycura-hrm-feature-by-feature-review|HRM feature-by-feature review]].
- After a mutation, screens refresh with Apollo `refetchQueries`, as across all LivelyCura client apps. The brief old value after Save, until the refetch lands, is accepted; don't propose `awaitRefetchQueries`, extra returned fields for cache writes, or `cache.modify` to change it. Source: [[../sources/livelycura-refetch-queries-after-mutation|Refetch queries after mutation]].
- This repository is a reference for the family’s Expo plus React Navigation structure.
- Keep workforce features locally owned; shared design-system components remain presentational.
- Everything people read names the app "SERLP Team" ("the SERLP Team app" where a sentence puts a person into it); bundle IDs `com.livelycura.loop*`, slug, schemes, storage keys, wire values like `LOOP_MOBILE`, identifiers and the old `/apps/mobile/loop/install` path stay as code names so installs and sent links keep working. Source: [[../sources/livelycura-loop-renamed-serlp-team|Loop renamed SERLP Team]].
- Distribution artwork uses the actual transparent app icon and the identity “Loop by SERLP” (superseded by SERLP Team on 2026-11-24; new artwork comes from the designer), with real app screenshots rather than invented UI. The proven iPhone export is `1242x2688` RGB without alpha; the Play composition uses one large center phone and two smaller side phones on solid brand green.

## Constraints

- Historical store-artwork outputs were kept in an external Downloads folder and are not present in the repository. Do not infer a current deployment-assets folder from the session.

## Decisions And Rationale

An independent workforce app gives employees a focused surface without exposing the ERP operator portal.

HRM leave balances were decided on 2026-10-22/23 and are not yet built: an annual leave request that does not fit the employee's balance is refused, and HR's only override is a reasoned adjustment. The full rules live on [[../projects/livelycura-backend|LivelyCura Backend]] (Leave Balances); source: [[../sources/livelycura-hrm-leave-balances-decisions|LivelyCura HRM Leave Balances Decisions]].

HRM holidays were decided on 2026-10-23 and are not yet built: employees are off on public holidays unless marked as working, Loop notifies them when a holiday is added, moved or deleted or when they are marked as working, and shows a "Holidays this year" list. The full rules live on [[../projects/livelycura-backend|LivelyCura Backend]] (Holidays); source: [[../sources/livelycura-hrm-holidays-decisions|LivelyCura HRM Holidays Decisions]].

Loop's personal information shows the employee record of the organization being viewed, never the shared login account, and HR edits never change the account. Source: [[../sources/livelycura-user-account-vs-employee|User account versus employee record]].
