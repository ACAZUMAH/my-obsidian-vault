# Think Like A User Direction

## Source

- Raw file: [Direction: think like a user, not only system-wise](../../raw/sources/2026-10-25-think-like-a-user-direction.md)
- Date: 2026-10-25
- Author: The user (verbatim messages)
- Ingested: 2026-10-25

## Core Claims

- Proposed fixes and decisions are judged by how real users would behave, not only by what the system technically allows.
- Guards against actions users would realistically never take (an HR manager deactivating the owner who hired them) are not worth proposing.
- Options are explained in the app's own words; internal terms such as "seat" confuse.

## Useful Details

- Raised while reviewing LivelyCura HRM Employees: the user rejected protecting the Owner employee from deactivation and Owner-role edits, and asked what a "seat" was.

## Contradictions Or Tensions

- Security-relevant guards still matter when the everyday risk is real (for example, staff granting themselves the Owner role); the direction targets unlikely scenarios, not genuine holes.
