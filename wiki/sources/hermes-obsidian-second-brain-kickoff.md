## Core Claims

- The user wants Hermes connected to Obsidian as a durable, linked second brain.
- The system should preserve how the user works so future models do not depend on the user repeating established preferences and procedures.
- Existing durable Hermes memories should seed the personal operating manual rather than remain isolated in a small prompt-memory store.

## Useful Details

- Hermes built-in memory remains useful for compact, always-loaded preferences and pointers.
- Obsidian is the long-form source of truth for linked workflows, decisions, conventions, corrections, and durable lessons.
- Mature repeatable procedures may also become Hermes skills; temporary task progress remains in session history rather than the wiki.
- The initial imported preferences concern sequential security remediation and a project-specific exclusion for `bora-capital-backend` migrations and cron jobs.

## Contradictions Or Tensions

- Automatic capture reduces forgetting, but indiscriminate capture would create noise and privacy risk. The system therefore captures durable, reusable information and excludes credentials, secrets, and short-lived task status by default.
