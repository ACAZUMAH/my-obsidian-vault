# LivelyCura HRM review: items shown on the current feature's screen still belong to their own module

- Date: 2026-11-10
- Author: the user (product owner), during the LivelyCura HRM feature-by-feature review in a Claude Code session
- Recorded from: the user's own message (quoted verbatim), relayed by the session agent

## Context

The review was on the Roles feature. The session's Roles report included a decision titled "Boxes that do nothing, and misleading names". It covered permission tick boxes and labels shown on the Roles permissions page but belonging to other modules and finished features: Accounting, Products, CRM, Fleet, Shifts, Attendance and Leaves (for example "Delete Products", "Legacy Accounting", "Create Leave"), plus one Roles box, "Delete Roles", which nothing checks because roles can only be deactivated. The report also listed items parked for other features.

## The user's words (verbatim)

- "what has that got to do with what we working on? why can't fucking stick what you are supposed to do. the delete role because we don't fucking have that we have only deactivate that's why there deactivate buttons there so I don't know what the fuck you mean boxes that do nothing and misleading names?"

## Rule

1. Something that appears on the current feature's screen still belongs to its own module or feature. A permission box for Products, Accounting or Leaves shown on the Roles page is that module's item, not a Roles item; park it silently.
2. Filter research or workflow briefs the same way before presenting them, and don't list parked items to the user, not even as a summary line.
