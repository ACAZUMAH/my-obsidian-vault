# LivelyCura: user account and employee record stay separate

- Date: 2026-10-25
- Author: the user, during the LivelyCura HRM Employees review in a Claude Code session
- Recorded from: the user's own message (quoted verbatim)

## Context

The session proposed copying HR's corrections of an employee's email or name onto the person's login (User) account so that Loop and sign-in codes would follow them.

## The user's words (verbatim)

"that's happening because on the loop app we are showing the account info instead of the employee details. when we are creating an employee we also create a user for them so that they can login. one mistake you will do is syncing it cus they are two different things. let me ask you a question you exactly the backend serves plenty client apps, say I am an employee at livelycura right, and I also have the check city which I order food from and I have my user info there. now someone or me updates my employee data at livelycura and you suggesting we sync so my user data at check city get's changed to does that make sense to you??"

## Rule

One User account serves every client app (including Check City); the Employee record is one organization's data. HR edits to an employee never change the User account. Staff screens such as Loop's personal info show the Employee record of the organization being viewed.
