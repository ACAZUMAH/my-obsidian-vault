# LivelyCura: serlp-mobile does everything the SERLP portal does

- Date: 2026-11-05
- Author: the user (product owner), during the LivelyCura HRM Employees work in a Claude Code session
- Recorded from: the user's own message (quoted verbatim, spelling kept), relayed by the session agent

## Context

While planning HRM Employees for `serlp-mobile`, the session offered options for how much of the feature the mobile app should do, with roles staying portal-only (SERLP portal, repository `livelycura-pharmacy-portal`).

## The user's words (verbatim)

- "anything the pharmacy portal does that selp mobile should also be able to do same, cuase it's the mobile version of the erp so what are you talking about"

## Rule

1. `serlp-mobile` is the mobile version of the ERP. Anything the SERLP portal (`livelycura-pharmacy-portal`) does, `serlp-mobile` must also be able to do, adapted to mobile.
2. Agents must never offer "portal-only" as an option, or ask how much of a feature belongs on `serlp-mobile`.
3. Anything the portal does that `serlp-mobile` cannot yet do is parity work to build, not a scope choice.
