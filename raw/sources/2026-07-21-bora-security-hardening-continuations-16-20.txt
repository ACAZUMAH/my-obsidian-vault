## Merged durable findings

- **Resolver boundary:** GraphQL resolvers adapt arguments and principal identity, call one owning service, and return; MongoDB `_id` to GraphQL `id` is the only intentional resolver-local transformation. Canonical loading, authorization, whitelisting, persistence, provider calls, enrichment, and notifications are service-owned.
- **Financial outcome invariant:** Notification failure after an accepted BCL deposit or withdrawal is logged but cannot turn provider success into failure or leave synchronization incomplete solely because notification delivery failed.
- **Authentication invariant:** Code purpose and complete observed state must remain bound through attempt reservation, expiration/exhaustion cleanup, successful consumption, and resend replacement. Stale same-purpose operations fail closed.
- **Recovery boundary:** Authenticated password change remains separate from public, rate-limited password recovery. Recovery validates and hashes the password before code consumption, issues no login tokens, and transactionally couples code consumption with password/session revocation.
- **Transaction semantics:** Only explicitly marked verification failures are handled as expected outcomes so attempt tracking or cleanup commits. Unexpected database/user-update failures abort and roll back consumption.
- **Deployment boundary:** The current model enforces one challenge per user, but no duplicate-record preflight or migration was found. Existing production data must be audited before relying on index creation.
- **User corrections:** Avoid unexplained abbreviations and define necessary technical terms. Current user-reviewed files and diffs outrank earlier assistant versions.
- **Historical verification:** Strict resolver and financial-correctness reviews passed in #16; final authentication security reviews passed in #19. These are historical outcomes, not fresh verification of the later dirty tree.
