# LivelyCura: staff copy says "request for" a shift (decided 2026-11-25)

- Date: 2026-11-25
- Author: the product owner, in a LivelyCura Claude Code session
- Recorded from: the owner's own messages (verbatim below), right after seeing "Request this shift?" on screen in SERLP Team
- Feature: HRM open shifts in the employee app SERLP Team (repo livelycura-loop-app) and the open-shift push sent by livelycura-backend, branch `feature/hrm`
- Status when recorded: built and committed (livelycura-loop-app `a6d0662`, livelycura-backend `2f72bdf57`); not yet pushed

## The owner's correction (verbatim)

- "some of the wording is wrong, it should either request for this shift or just request not request this shift"

## What the session found and offered

- "Request this shift" wording appeared in five places staff read: four in SERLP Team and one in a backend push notification.
- The session laid out three wording options. Option 1 was "request for" everywhere staff read it. The full text of options 2 and 3 was not kept in the session record; the owner's own message names the other form, "just request".

## The owner's answer (verbatim)

- "Option 1"

## How the session applied it

- SERLP Team button: "Request this shift" became "Request for this shift" ("Take this shift" for first-come shifts is unchanged).
- SERLP Team confirmation title: "Request this shift?" became "Request for this shift?"
- A shift the person can't take: "You can't request this shift." became "You can't request for this shift."
- After withdrawing a request (confirmation and toast): "... you can request it again." became "... you can request for it again."
- Backend push for a published or reopened open shift that waits for approval: "Tap to request it." became "Tap to request for it."
- "Request" used as a noun stays: "Send request", "Withdraw your request?", "Request sent".
